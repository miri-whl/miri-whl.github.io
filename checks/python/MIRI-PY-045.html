MIRI-PY-045 — Precomputed code index declared

A precomputed code index ships in the wheel and sdk-manifest.json declares where it is

should severity LOW · 1 weight 1 Miri Wheel Ext. §5.5SCIP — Code Intelligence ProtocolWhen LLMs Lag Behind: Knowledge Conflicts from Evolving APIs in Code GenerationPEP 770

Definition: standards/python/checks/MIRI-PY-045.yaml · view · raw

Violation
greetlib-1.1.0.dist-info/ RECORD scip/index.scip <- present, 1.4 MB sdk-manifest.json: {"api_index": {...}} <- no code_index The index is in the wheel and no consumer can discover it: nothing declares the path, nothing names the format, and a consumer that does not already expect .dist-info/scip/index.scip has no reason to look. A carried artifact nobody can find is the same as an absent one.
Compliant
greetlib-1.1.0.dist-info/ RECORD <- lists scip/index.scip with its sha256 and size scip/index.scip sdk-manifest.json: "code_index": { "path": ".dist-info/scip/index.scip", "format": "scip", "reduction": "occurrences-stripped" } A consumer reads code_index, sees a format it can or cannot decode, and falls back to api_index if it cannot - which is why the declaration matters more than the index.

Why this matters

Coding agents write against the API they were trained on. Measured, not assumed: a benchmark of 270 real API updates across eight Python libraries (NumPy, Pandas, SciPy, scikit-learn, JAX, Keras, TensorFlow, PyTorch) found 25.36% of generations ignored the update entirely, 16.4% used only the removed API, and 12.3% mixed old and new APIs in one file. Supplying structured API documentation alongside the request raised the share of generated code that executes from 42.55% to 66.36% - the largest single intervention measured, where chain-of-thought prompting moved it 2.34 points. The study supplied that documentation by hand in a prompt; a wheel can ship it, versioned with the code, with nobody assembling a context. 128 of those 270 updates were MODIFICATIONS - symbols that kept their name and changed shape - which is the class a name-keyed index cannot detect at all and the one that produces the mixed-API failure, because the name still resolves and the call is wrong. A published index format also makes a release delta computable from two artifacts rather than declared: signature-level identity is what MIRI-PY-043 compares and what a name set cannot express. Proposed by the miri-py team, who measured the alternatives and published the negative result alongside the positive one - read whole, an index costs more tokens than reading the source; queried for one symbol it is 22x cheaper. That asymmetry is why this check asks for the index to be DECLARED rather than assumed readable.

Definition

A wheel is the only thing an offline consumer has, so structure that would otherwise require running an analyzer has to be precomputed and carried. This check verifies: an index is present, it is listed in RECORD, and sdk-manifest.json code_index names its path and format so a consumer can discover it and decide whether it can read it before opening it. What this check does NOT verify is that the index covers the public surface: confirming coverage means decoding the index, and the standard declines to require a decoder of every linter for the same reason it declines to require one of every consumer. Coverage is therefore a producer obligation stated in Miri Wheel Extensions §5.5 and not a clause here - said plainly rather than implied, because a presence-only check that reads as a coverage check is the vacuous pass this standard names elsewhere.

When it fires

  • The wheel ships no precomputed code index under .dist-info/ and sdk-manifest.json carries no code_index
  • sdk-manifest.json code_index names a path that is absent from the wheel, or present but unlisted in RECORD
  • code_index.format is outside the closed set the schema declares
  • An index file is present under .dist-info/ that no code_index pointer declares, so a consumer has no discoverable way to know it is there or what format it is in

How to fix it

Ship a reduced SCIP index under .dist-info/ and declare its path and format in code_index.

  1. Produce a SCIP index for the package at build time. The standard names the format and not the producer, exactly as it names the wheel format and not the build backend
  2. Reduce it before shipping - a full index measured 62% of a 1.87 MB wheel, where the same index with reference occurrences removed measured 20% - and see Miri Wheel Extensions §5.5 for which sections a consumer needs
  3. Write the index under .dist-info/ beside the SBOM documents PEP 770 places there, so one convention covers both precomputed artifacts
  4. Declare it in sdk-manifest.json code_index with its path and format, and confirm the build listed it in RECORD
