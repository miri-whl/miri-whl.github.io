MIRI-PY-010 — api-graph.json valid

If present, validates against schema

should severity LOW · 1 weight 1 Agent Metadata §4.5schema

Definition: standards/python/checks/MIRI-PY-010.yaml · view · raw

Violation
api-graph.json: {"version": "1.0", "nodes": {"Client": {"type": "class"}}, "edges": [{"from": "QueryBuilder", "to": "Client", "relationship": "uses"}]} # QueryBuilder is not in nodes — the edge asserts a relationship # for a component the graph never declares
Compliant
{"version": "1.0", "nodes": {"Client": {"type": "class"}, "QueryBuilder": {"type": "class"}}, "edges": [{"from": "QueryBuilder", "to": "Client", "relationship": "uses"}]} # every edge endpoint resolves to a declared node

Why this matters

api-graph.json is consumed for relationship reasoning — which classes cooperate, what a workflow touches — and its value inverts when the data is wrong: an edge whose from or to names a node that does not exist reads, to a consumer, exactly like a real relationship, so the agent asserts cooperation between components that were never connected. Because the file is optional, an absent graph degrades gracefully to manifest-only reasoning, while a present-but-broken graph is strictly worse than none; the check therefore validates only what actually ships.

Definition

The agent-metadata directory is the wheel's machine-readable surface; every file in it must be present, schema-valid, and generated at build time so agents can consume it without parsing or guessing. This check verifies: If present, validates against schema.

When it fires

  • agent-metadata/api-graph.json is present and fails api-graph-v1.json validation (version, nodes, or edges missing)
  • An edge lacks from, to, or relationship, or either endpoint names a key absent from nodes
  • A workflow's steps reference components that appear nowhere in nodes

How to fix it

Regenerate api-graph.json or fix the dangling edge.

  1. Regenerate the graph in the same build pass that produces sdk-manifest.json, so both derive from one source scan
  2. Fail the build on dangling references: every edge endpoint and workflow step must resolve to a nodes key
  3. If the graph cannot be generated reliably, omit the file — this check does not fire on absence
