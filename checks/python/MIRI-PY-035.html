MIRI-PY-035 — Runtime warnings fire

Importing/calling deprecated interfaces emits DeprecationWarning

should severity MINOR · 2 weight 2 conditional requires execution PEP 565

Definition: standards/python/checks/MIRI-PY-035.yaml · view · raw

Violation
def legacy_connect(self): """Deprecated: use connect() instead.""" # docstring only return self.connect() # catch_warnings(record=True) captures nothing — consumer CI logs stay clean until the removal breaks them
Compliant
@deprecated("legacy_connect() is deprecated; use connect(). Removal: 3.0.0") def legacy_connect(self): return self.connect() # pytest output: DeprecationWarning: legacy_connect() is deprecated; use connect(). Removal: 3.0.0

Why this matters

Since PEP 565 (Python 3.7) the default filters display a DeprecationWarning only when it is triggered by code running in __main__; inside imported libraries it is silent unless a test runner or -W/-X dev re-enables it — and pytest surfaces warnings by default, which makes consumers' CI the one channel that reliably reaches people who read neither metadata nor type checkers. That channel carries nothing unless the warning is actually emitted: a deprecation recorded only in a docstring, changelog, or migration-guide.json gives the filters nothing to show. The PEP 702 decorator (warnings.deprecated on Python ≥3.13, typing_extensions.deprecated earlier) closes both routes at once — static call-site flagging plus the runtime DeprecationWarning (Lifecycle §6.1).

Definition

Agents working from frozen model weights cannot read changelogs; deprecation must be marked in code, inventoried in metadata, and never resolved by silent removal. This check verifies: Importing/calling deprecated interfaces emits DeprecationWarning.

When it fires

  • Calling or importing an interface listed in migration-guide.json deprecations under warnings.catch_warnings(record=True) with simplefilter("always") captures no warning
  • A warning is emitted but its category is not DeprecationWarning or a subclass (e.g. UserWarning, or a bare print to stderr)
  • The deprecation exists only as docstring or comment text, with no PEP 702 decorator and no warnings.warn call on the executable path

How to fix it

Ensure the PEP 702 decorator (or warnings call) fires at runtime.

  1. Decorate the interface with warnings.deprecated(...) (Python ≥3.13) or typing_extensions.deprecated(...); the decorator emits DeprecationWarning at call time and marks call sites for type checkers
  2. For deprecated module attributes, emit from a module-level __getattr__ via warnings.warn(msg, DeprecationWarning, stacklevel=2)
  3. Pin the behavior in the test suite: with pytest.warns(DeprecationWarning, match="legacy_connect"): client.legacy_connect()
