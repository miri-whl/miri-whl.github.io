MIRI-PY-030 — No silent removals

Every public interface removed since the prior release was listed in an earlier release's deprecations

must severity CRITICAL · 5 weight 5 conditional requires previous-release Lifecycle §6.4-2

Definition: standards/python/checks/MIRI-PY-030.yaml · view · raw

Violation
1.9.0 sdk-manifest.json: functions: ["execute", "query", "connect"] 2.0.0 sdk-manifest.json: functions: ["query", "connect"] # execute() gone; no release's deprecations array ever listed it — # callers learn via AttributeError: module has no attribute 'execute'
Compliant
1.8.0: @deprecated("Use query() instead; removed in 2.0.0") + deprecations entry 1.8.x–1.9.x: execute() works, warns, for two minor releases 2.0.0: execute() removed; the removal matches its announced removal_version

Why this matters

A silent removal converts every dependent from working to broken with zero machine-readable warning — the first signal any consumer receives is AttributeError in production, and agents working from frozen model weights keep generating calls to the vanished interface indefinitely. The reference incident is kubectl's --export flag: deprecated in v1.14 and removed in v1.18, it still broke CI pipelines and resource-cloning scripts at removal because the deprecation lived in a human-readable warning no automation consumed; a removal with no deprecation trail at all is strictly worse. §6.4-2 exists because no ecosystem tool checks this — API-diff tools detect the removal but never cross-check it against declared deprecations.

Definition

Agents working from frozen model weights cannot read changelogs; deprecation must be marked in code, inventoried in metadata, and never resolved by silent removal. This check verifies: Every public interface removed since the prior release was listed in an earlier release's deprecations.

When it fires

  • A public interface present in the previous release's sdk-manifest.json is absent from the current release's
  • That interface appears in no earlier release's migration-guide.json deprecations array

How to fix it

Deprecate first: marker + inventory entry + grace period, then remove.

  1. Reinstate the interface in a patch release — the removal shipped without its contract
  2. Deprecate it properly: PEP 702 marker naming replacement and removal_version (MIRI-PY-028), derived inventory entry (MIRI-PY-029), and a grace period of at least two releases per the PEP 387 policy shape
  3. Remove it only in the announced version, and gate releases on the §6.4-2 coherence check in CI so the diff-against-previous-release runs before publish, not after
