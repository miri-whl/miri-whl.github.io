MIRI-PY-036 — Discovery and manifest verification

Discovery functions work and sdk-manifest.json api_index agrees with the installed API surface in both directions

must severity MEDIUM · 3 weight 3 requires execution Miri Wheel Ext. §6Agent Metadata Spec §5.4 (Generation Invariants)

Definition: standards/python/checks/MIRI-PY-036.yaml · view · raw

Violation
$ pip install weather_sdk-1.2.0-py3-none-any.whl $ python -c "import weather_sdk; weather_sdk.show_quickstart()" AttributeError: module 'weather_sdk' has no attribute 'show_quickstart' # examples/ is also missing from the wheel: package data was never declared, only the source tree had it
Compliant
>>> import weather_sdk >>> weather_sdk.list_examples() ['quickstart', 'authentication', 'error_handling'] >>> weather_sdk.get_agent_metadata()["package"]["version"] '1.2.0' # matches dist-info/METADATA and the files under agent-metadata/

Why this matters

The §6.1 functions (get_examples_dir, get_agent_metadata, show_quickstart, …) are the runtime entry point to everything else the standard ships — the wheel-side equivalent of a CLI's --describe; when they raise or return paths that do not exist, agents fall back to guessing file locations by convention, the exact behavior the standard exists to end. The characteristic failure is wheel-versus-source drift: the functions work in the developer's checkout, but the data directories were never declared as package data, so the built wheel omits them and get_examples_dir() returns a path that exists nowhere after pip install. Only executing the functions against the installed wheel detects this class. This check is also the one place the standard verifies that sdk-manifest.json's api_index — the surface agents generate code from — actually matches the installed package; a manifest listing methods the code lacks sends agents straight to AttributeError, so the api_index must be checked against the real surface, not merely schema-valid.

Definition

Miri metadata must be discoverable at runtime and must never make the package worse for non-Miri consumers. This check verifies: package-level discovery functions are importable and return coherent data, every sdk-manifest.json api_index entry resolves against the installed package, and every public definition the installed package exposes has an entry, unless a declared surface_scope excludes it. Both directions are required: before 0.8.0 only the first was, so an index describing half its package passed cleanly.

When it fires

  • Any §6.1 discovery function is absent from the package's top-level namespace after installing the wheel into a clean venv
  • Calling a discovery function raises, or returns a path that does not exist in the installed distribution
  • Returned data contradicts the shipped files — e.g. list_examples() disagrees with AGENT_EXAMPLES.json or with the contents of examples/, or get_agent_metadata() disagrees with agent-metadata/
  • An sdk-manifest.json api_index entry does not resolve against the installed package — the named class or function is absent, or a listed key_methods / init_params entry disagrees with the object's actual inspect.signature
  • An api_index entry names a console-script entry point declared in the wheel's entry_points (console_scripts) — the CLI surface belongs in the CLI standard's --describe, not api_index, and MUST be excluded from it (Generation Invariant §5.4)
  • A public definition importable from the installed package has no api_index entry reaching it, counting a module entry's members and a class entry's key_methods as reaching one. PUBLIC is defined in Agent Metadata §5.4 rather than left to the linter. It covers a name not beginning with _ (except __init__ and __call__), governed by __all__ where a module declares one, counted once at its definition rather than at each re-export, and excluding inherited methods. Where surface_coverage is declared, a definition matched by a surface_scope.exclude pattern is out of scope and does not fire; where surface_coverage is absent or complete, every public definition is in scope. Console-script entry points are excluded by the clause above and never fire this one. This clause needs no execution, because the wheel carries its own sources and the comparison is a pure static one. It sits in this check for cohesion, and MIRI-PY-043 deliberately does not depend on it, so that a linter declining to execute code can still settle coverage for itself

How to fix it

Implement the package-level discovery functions over the generated metadata.

  1. Implement each function as a thin reader over the installed files via importlib.resources.files(...), never over remembered build-tree paths
  2. Declare examples/, docs/, templates/, and agent-metadata/ as package data ([tool.setuptools.package-data] or the build backend's equivalent) so they actually enter the wheel
  3. Test the artifact, not the source tree: pip install dist/*.whl into a fresh venv in CI, call every §6.1 function, and assert on the results
  4. Generate api_index from the package's actual importable surface (AST or introspection) at build time, and assert in CI that every entry resolves after install — the manifest agents generate code from must not be able to lie
  5. Exclude console-script entry points and the CLI command surface from api_index at generation time; the CLI is described by the CLI standard's --describe, not this file (Generation Invariant §5.4)
  6. Where the index deliberately covers part of the package, declare it: set surface_coverage to declared and list the excluded patterns in surface_scope.exclude, so an omission reads as a decision rather than as a defect
