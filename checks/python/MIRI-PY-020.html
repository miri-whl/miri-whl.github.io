MIRI-PY-020 — Distribution & registry declared

distribution set; registry a well-formed index URL

must severity MEDIUM · 3 weight 2 Lifecycle §3.1

Definition: standards/python/checks/MIRI-PY-020.yaml · view · raw

Violation
lifecycle.json: "identity": {"purl": "pkg:pypi/example-internal@3.2.0"} <- distribution and registry absent: a consumer defaults to public OSV for example-internal, an internal-only name, and the empty response reads as "not vulnerable"
Compliant
lifecycle.json: "identity": { "purl": "pkg:pypi/example-internal@3.2.0?repository_url=https://pypi.internal.example/simple/", "distribution": "private", "registry": "https://pypi.internal.example/simple/" } (consumers skip public OSV as authoritative and can flag any install not originating from the declared registry)

Why this matters

identity.distribution selects which specification defaults apply — §4 open source or §5 private — and identity.registry names the index the artifact is published to, the one field that lets a consumer compare declared origin against actual install origin, the dependency-confusion tell called out in §3.1. The stakes are asymmetric and silent: public OSV queried for a private-only name returns an empty result indistinguishable from "not vulnerable" (§5.1), so a wheel that leaves distribution undeclared defaults its consumers into exactly the lookup that lies to them.

Definition

Vulnerability and currency verdicts are computed externally by joining declared identity against advisory databases; a wheel that misdeclares identity or sources silently breaks that join. This check verifies: distribution set; registry a well-formed index URL.

When it fires

  • identity.distribution is absent or not one of "open-source" / "private"
  • identity.registry is absent, not an absolute http(s) URL, or a placeholder value (e.g. "TBD")
  • the declarations contradict each other: distribution "private" with registry https://pypi.org/simple/, or "open-source" with an internal-only index
  • registry points at a project page (e.g. https://pypi.org/project/example-sdk/) rather than an installable index URL

How to fix it

Declare distribution (open-source or private) and the publishing registry URL.

  1. Declare both fields in the Miri build configuration, e.g. [tool.miri.lifecycle] distribution = "open-source", registry = "https://pypi.org/simple/"
  2. For private packages set distribution = "private" and point registry at the internal index (e.g. https://pypi.internal.example/simple/) — the same URL carried in the purl's repository_url qualifier (§5.1)
  3. Use the installable simple-index URL, not the project page, so consumers can compare it directly against pip's actual install origin
