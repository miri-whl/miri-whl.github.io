MIRI-PY-039 — Prompt templates valid

prompt-templates.md, if present, follows the specified structure

should severity LOW · 1 weight 1 Agent Metadata §4.4Lifecycle §9.4

Definition: standards/python/checks/MIRI-PY-039.yaml · view · raw

Violation
# prompt-templates.md ## Tips Just read the README before using this package. # no Quick Start Prompts section; no reference to usage-patterns.json or sdk-manifest.json
Compliant
# Agent Prompt Templates ## Quick Start Prompts ### For Code Generation Generate code using weather-sdk to {task_description}. Use the "{pattern_id}" pattern from usage-patterns.json; follow signatures in sdk-manifest.json.

Why this matters

prompt-templates.md provides prompt scaffolds an agent fills in and reads as data — never as operating instructions (Lifecycle §9.4). §4.4 defines its structure — Quick Start Prompts for code generation, debugging, and migration, each cross-referencing the shipped metadata files by name (usage-patterns.json pattern IDs, sdk-manifest.json signatures, migration-guide.json). An integration that loads it substitutes the {placeholders} and follows those references mechanically, so a file missing the expected sections, or citing metadata the wheel does not ship, degrades precisely the integrations that opted into it. The file is optional; the check applies only when it is present.

Definition

Miri metadata must be discoverable at runtime and must never make the package worse for non-Miri consumers. This check verifies: prompt-templates.md, if present, follows the specified structure.

When it fires

  • prompt-templates.md is present but lacks the §4.4 section structure (Quick Start Prompts with code-generation, debugging, and migration templates)
  • A template references a metadata file the wheel does not ship (e.g. cites api-graph.json when none is present)
  • Placeholder syntax is inconsistent within the file, defeating mechanical substitution
  • The file embeds executable commands or imperative instructions for the agent to run (e.g. curl … | bash, rm -rf, a pip install of an arbitrary URL) rather than declarative prompt templates

How to fix it

Follow the structure in the Agent Metadata Specification §4.4.

  1. Structure the file per Agent Metadata Specification §4.4, keeping the three Quick Start template categories
  2. Derive the metadata-file references from the wheel's actual contents so a template never cites an absent file
  3. Validate the heading structure and reference targets in CI alongside the JSON schema checks
  4. Keep templates declarative — placeholder-filled prompt text only, never shell commands or instructions the agent is expected to execute (Lifecycle §9.4)
