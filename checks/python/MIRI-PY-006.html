MIRI-PY-006 — agent-metadata/ present

Directory exists in the package

must severity CRITICAL · 5 weight 2 Miri Wheel Ext. §3.2

Definition: standards/python/checks/MIRI-PY-006.yaml · view · raw

Violation
src/example_sdk/agent-metadata/sdk-manifest.json # exists in the repo unzip -l dist/example_sdk-2.1.0-py3-none-any.whl | grep agent-metadata # (no output) — the backend shipped only *.py; every installed copy # of the package lacks the directory
Compliant
unzip -l dist/example_sdk-2.1.0-py3-none-any.whl example_sdk/agent-metadata/sdk-manifest.json example_sdk/agent-metadata/usage-patterns.json example_sdk/agent-metadata/lifecycle.json

Why this matters

Wheel Extensions §3.1.2 places agent-metadata/ inside the import package specifically so a plain pip install delivers it and importlib.resources can read it with no network access; it is the root the entire Miri surface hangs from, and without it an agent is back to the linear README-and-guesswork path the standard exists to eliminate. The characteristic failure is packaging, not authorship, and it is silent: setuptools ships only *.py unless package-data names the JSON files, and hatchling's default file selection excludes git-ignored paths — which build-time-generated metadata usually is — so the directory exists in the repository, vanishes from the built wheel, and nothing warns.

Definition

The agent-metadata directory is the wheel's machine-readable surface; every file in it must be present, schema-valid, and generated at build time so agents can consume it without parsing or guessing. This check verifies: Directory exists in the package.

When it fires

  • No agent-metadata/ directory exists under any import package in the wheel (checked against RECORD and the archive listing)
  • The directory exists but contains none of the files the specification defines (sdk-manifest.json, usage-patterns.json, lifecycle.json, ...)
  • The directory's files are present but unreadable (zero-byte or undecodable)

How to fix it

Add the agent-metadata/ directory and generate its files at build time.

  1. Run the Miri generation step at build time so src/<package>/agent-metadata/ is populated before the backend collects files
  2. Make the backend include it: setuptools needs [tool.setuptools.package-data] example_sdk = ["agent-metadata/*.json", "agent-metadata/*.md"]; hatchling needs [tool.hatch.build] artifacts = ["*/agent-metadata/*"] because its defaults exclude git-ignored generated files
  3. Verify the built artifact, not the source tree: unzip -l dist/example_sdk-*.whl | grep agent-metadata/
