MIRI-PY-021 — Advisory sources present

≥1 entry in advisory_sources, valid type and URL

must severity HIGH · 4 weight 3 Lifecycle §3.1OSV schema

Definition: standards/python/checks/MIRI-PY-021.yaml · view · raw

Violation
lifecycle.json: "identity": {"purl": "pkg:pypi/example-package@2.1.0", ...}, "advisory_sources": [], "update_check": {...} # consumers skip the OSV join entirely and report the package clean
Compliant
lifecycle.json: "advisory_sources": [ {"type": "osv", "ecosystem": "PyPI", "url": "https://api.osv.dev/v1/query", "authoritative": true} ]

Why this matters

Every vulnerability verdict in this specification is computed by the consumer, by POSTing the package's purl to a declared OSV-compatible endpoint (§2.1: sources, not verdicts). With advisory_sources empty there is no endpoint to join against, so the security leg of the two-question workflow (§7) silently evaluates to nothing — and downstream tooling routinely renders "no sources consulted" identically to "no known vulnerabilities". The package looks scanned while nothing was ever queried.

Definition

Vulnerability and currency verdicts are computed externally by joining declared identity against advisory databases; a wheel that misdeclares identity or sources silently breaks that join. This check verifies: ≥1 entry in advisory_sources, valid type and URL.

When it fires

  • advisory_sources in agent-metadata/lifecycle.json is absent, null, or an empty array
  • An entry's type is not one of osv, osv-internal, or osv-local
  • An entry's url fails URL parsing (or, for osv-local, names no readable path), or is a placeholder value such as TODO or an example.com host
  • No entry carries authoritative: true

How to fix it

Declare at least one OSV-compatible advisory endpoint.

  1. For distribution: open-source, declare the public endpoint: {"type": "osv", "ecosystem": "PyPI", "url": "https://api.osv.dev/v1/query", "authoritative": true} — per §4.1 build tools SHOULD inject this automatically
  2. For distribution: private, declare an internal source per §5.2 (osv-internal endpoint or osv-local archive)
  3. Regenerate lifecycle.json at build time (§2.4) rather than hand-patching the array
