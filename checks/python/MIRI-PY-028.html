MIRI-PY-028 — PEP 702 markers

Every interface listed as deprecated carries @deprecated; decorator message names replacement + removal version

must severity HIGH · 4 weight 4 conditional PEP 702Lifecycle §6.1

Definition: standards/python/checks/MIRI-PY-028.yaml · view · raw

Violation
# migration-guide.json lists legacy_connect() as deprecated, but the code reads: def legacy_connect(host: str) -> Connection: return connect(host) # no marker: IDEs, type checkers, runtime all silent
Compliant
@deprecated("Use connect() instead; legacy_connect() will be removed in 3.0.0") def legacy_connect(host: str) -> Connection: return connect(host) # pyright/mypy flag every call site; calling emits DeprecationWarning

Why this matters

The PEP 702 @deprecated decorator (warnings.deprecated on Python ≥3.13, typing_extensions.deprecated ≥4.5 earlier) is the one marking mechanism that reaches every consumer class at once: static type checkers and IDEs flag call sites without executing code, the runtime emits DeprecationWarning under PEP 565 semantics, and §6.2 derives the machine-readable inventory from it at build time. A deprecation recorded only in a changelog is invisible to type checkers; one expressed only as warnings.warn in the function body is invisible statically — each leaves at least one consumer class calling the interface until it vanishes. Without the replacement and removal version in the message, the warning says stop but not what to do instead or by when.

Definition

Agents working from frozen model weights cannot read changelogs; deprecation must be marked in code, inventoried in metadata, and never resolved by silent removal. This check verifies: Every interface listed as deprecated carries @deprecated; decorator message names replacement + removal version.

When it fires

  • A function, class, method, or overload listed in migration-guide.json deprecations carries no @deprecated decorator (neither warnings.deprecated nor typing_extensions.deprecated); module-level attributes and constants — which cannot carry the decorator — are exempt and are deprecated via a module __getattr__ (MIRI-PY-035, Lifecycle §6.1)
  • A decorator message names no replacement interface
  • A decorator message names no planned removal version

How to fix it

Mark it with warnings.deprecated (PEP 702) naming the replacement and removal version.

  1. Apply the marker: from warnings import deprecated on ≥3.13, from typing_extensions import deprecated below (dual-import via a compatibility shim if the package supports both)
  2. Write the message as replacement plus deadline, e.g. @deprecated("Use connect() instead; legacy_connect() will be removed in 3.0.0")
  3. Keep the marked implementation working through the PEP 387-shaped grace period (§6.1) — the marker announces removal, it does not perform it
