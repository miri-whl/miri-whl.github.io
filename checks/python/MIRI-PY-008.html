MIRI-PY-008 — usage-patterns.json valid

Present and validates against schema

must severity MEDIUM · 3 weight 3 Agent Metadata §4.2schema

Definition: standards/python/checks/MIRI-PY-008.yaml · view · raw

Violation
usage-patterns.json: {"version": "1.0", "generated_at": "2026-08-01T12:00:00Z", "patterns": [{"name": "Basic connection", "description": "Connect and query"}]} # the pattern has no id (nothing can reference it) and no code (nothing to insert)
Compliant
{"version": "1.0", "generated_at": "2026-08-01T12:00:00Z", "patterns": [{"id": "basic_connection", "name": "Basic connection", "description": "Connect and run one query", "complexity": "beginner", "category": "connection", "code": "from example_sdk import Client\nclient = Client(dsn)\nclient.connect()"}]}

Why this matters

Usage patterns exist so agents insert vetted idioms instead of re-deriving them, which is why usage-patterns-v1.json makes id, name, description, complexity, category, and code mandatory for every pattern. The id is load-bearing beyond this file: sdk-manifest.json's usage_patterns arrays, migration-guide.json's affected_patterns, and prompt templates all reference patterns by id, so an entry with no stable id — or no code body — breaks cross-referencing for every file that points at it, not just this one.

Definition

The agent-metadata directory is the wheel's machine-readable surface; every file in it must be present, schema-valid, and generated at build time so agents can consume it without parsing or guessing. This check verifies: Present and validates against schema.

When it fires

  • agent-metadata/usage-patterns.json is absent
  • The top level lacks version, generated_at, or patterns
  • A pattern entry lacks any of id, name, description, complexity, category, or code
  • A categories or learning_paths entry lists a pattern id that no pattern defines

How to fix it

Regenerate usage-patterns.json; every pattern needs id and code.

  1. Regenerate usage-patterns.json at build time from curated sources (examples/, tests/) per Agent Metadata §5.1
  2. Assign every pattern a stable snake_case id and treat a rename like an API rename: update every referencing file in the same change
  3. Validate before packaging: check-jsonschema --schemafile usage-patterns-v1.json src/example_sdk/agent-metadata/usage-patterns.json
