MIRI-PY-018 — lifecycle.json valid

Present and validates against schema

must severity CRITICAL · 5 weight 4 Lifecycle Spec §3schema

Definition: standards/python/checks/MIRI-PY-018.yaml · view · raw

Violation
agent-metadata/ contains only: sdk-manifest.json usage-patterns.json (no lifecycle.json: no purl, no advisory_sources — scanners have no join key, and the package silently drops out of every vulnerability and currency check)
Compliant
agent-metadata/lifecycle.json (validates against lifecycle-v1.json): {"miri_lifecycle_version": "0.1", "generated_at": "2026-08-15T14:02:07Z", "identity": {"purl": "pkg:pypi/example-sdk@1.2.0", "distribution": "open-source", "registry": "https://pypi.org/simple/"}, "advisory_sources": [{"type": "osv", "ecosystem": "PyPI", "url": "https://api.osv.dev/v1/query", "authoritative": true}], "update_check": {"type": "pypi-json", "url": "https://pypi.org/pypi/example-sdk/json"}, "support": {"status": "active"}}

Why this matters

lifecycle.json is the package's entire identity and advisory declaration (Lifecycle §3): vulnerability and currency verdicts are joins computed by consumers, and without the file there is no join key and no source list, so the package is silently exempt from every scan. The failure is worst exactly where §1 warns it is invisible — for private packages, public OSV returns an empty result for an unknown name, indistinguishable from "not vulnerable". Schema validity is equally load-bearing: consumers parse against lifecycle-v1.json, and a file missing identity or advisory_sources fails the join the same way absence does.

Definition

Vulnerability and currency verdicts are computed externally by joining declared identity against advisory databases; a wheel that misdeclares identity or sources silently breaks that join. This check verifies: Present and validates against schema.

When it fires

  • agent-metadata/lifecycle.json is absent from the wheel
  • the file fails Draft-07 validation against lifecycle-v1.json (missing required members, enum violations, additionalProperties, malformed purl pattern)
  • advisory_sources is empty, or an entry's url is a placeholder rather than a well-formed URL or path (Lifecycle §8, item 3: reachable-by-construction)

How to fix it

Add agent-metadata/lifecycle.json; validate against lifecycle-v1.json.

  1. Generate agent-metadata/lifecycle.json at build time from pyproject.toml plus [tool.miri] configuration (Lifecycle §2.4) — never hand-maintain it per release
  2. Validate in CI: python3 -c "import json, jsonschema; jsonschema.validate(json.load(open('src/pkg/agent-metadata/lifecycle.json')), json.load(open('schemas/lifecycle-v1.json')))"
  3. Populate at least one real advisory_sources entry: the public OSV endpoint (https://api.osv.dev/v1/query, ecosystem PyPI) for open source per §4.1, or an osv-internal endpoint for private per §5.2
