MIRI-PY-012 — Version coherence

sdk_version in every metadata file equals the wheel version

must severity HIGH · 4 weight 3 Agent Metadata §4.1

Definition: standards/python/checks/MIRI-PY-012.yaml · view · raw

Violation
example_sdk-1.2.0-py3-none-any.whl: METADATA: Version: 1.2.0 sdk-manifest.json: "sdk_version": "1.1.0" <- still documents execute(), renamed to query() in 1.2.0 lifecycle.json: "purl": "pkg:pypi/example-sdk@1.1.0"
Compliant
example_sdk-1.2.0-py3-none-any.whl: METADATA: Version: 1.2.0 sdk-manifest.json: "sdk_version": "1.2.0" lifecycle.json: "purl": "pkg:pypi/example-sdk@1.2.0" (all derived from the single [project] version at build time)

Why this matters

PEP 427 binds the version in a wheel's filename to its dist-info METADATA and pip refuses wheels where the two disagree; this check extends the same invariant to the agent-metadata surface. A manifest carrying a different sdk_version means the agent is reading API documentation for a release it is not running: the specification's own migration example — execute() renamed to query() in 1.2.0 — shows how a 1.1.0 manifest inside a 1.2.0 wheel directs the agent to call a method that no longer exists, and the resulting AttributeError points at the agent's code, not at the stale metadata that caused it.

Definition

The agent-metadata directory is the wheel's machine-readable surface; every file in it must be present, schema-valid, and generated at build time so agents can consume it without parsing or guessing. This check verifies: sdk_version in every metadata file equals the wheel version.

When it fires

  • sdk_version in sdk-manifest.json is not exactly (byte-for-byte) equal to the wheel's METADATA Version
  • any other agent-metadata file carrying the package version (the @version in lifecycle.json identity.purl, migration-guide.json to_version) is not exactly equal to METADATA Version
  • version strings are canonically equal but not textually identical (e.g. a 1.2.0 manifest in a 1.2 wheel); this check requires exact string equality — matching MIRI-PY-019 — so near-misses still fire

How to fix it

Derive sdk_version from the single package version source at build time.

  1. Keep one version source: [project] version in pyproject.toml, or dynamic versioning via the build backend's VCS plugin
  2. Have the generator read that source (importlib.metadata.version() against the built package) instead of accepting a version argument that can drift
  3. Assert sdk_version == METADATA Version for every metadata file in CI after python -m build and before upload; fail the release on any mismatch
