MIRI-PY-003 — Version scheme valid

Version parses under the canonical scheme

must severity HIGH · 4 weight 2 PEP 440

Definition: standards/python/checks/MIRI-PY-003.yaml · view · raw

Violation
METADATA: Version: v1.2-final # packaging >= 22.0 raises InvalidVersion; setuptools >= 66 refuses to # process the distribution and pip cannot compare it against any range
Compliant
METADATA: Version: 2.1.0 # release candidates as 2.1.0rc1, hotfix metadata as 2.1.0.post1 — # all orderable by packaging.version

Why this matters

Version ordering is the substrate for every lifecycle comparison Miri specifies — update_check staleness, advisory ranges, removal_version sanity (MIRI-PY-032) — and PEP 440 is the only scheme the ecosystem's comparators implement. The tolerance for anything else is gone: packaging 22.0 (December 2022) removed LegacyVersion, so setuptools >= 66 and current pip raise InvalidVersion on non-conforming version strings, and a single such package can break tooling for the whole environment that contains it. PEP 440 additionally forbids local version labels on public index servers, and PyPI rejects uploads that carry them.

Definition

Miri builds on the existing packaging standards rather than replacing them; a wheel that violates the baseline cannot carry trustworthy agent metadata. This check verifies: Version parses under the canonical scheme.

When it fires

  • The Version in METADATA fails packaging.version.Version() parsing (e.g. v1.2-final, 2024-06, 1.0-SNAPSHOT)
  • The version carries a local label (+...) while lifecycle.json declares a public registry
  • The wheel filename's version segment disagrees with the Version field

How to fix it

Use a PEP 440 version such as 1.2.0 or 1.2.0rc1.

  1. Adopt PEP 440 forms: 1.2.0, 1.2.0rc1, 1.2.0.post1, 1.2.0.dev3
  2. When versions derive from git tags, use setuptools-scm or hatch-vcs, which strip v prefixes and emit valid .devN forms instead of raw git describe output
  3. Reserve local labels such as 2.1.0+internal.1 for private indexes; strip them before any public upload
  4. Fail the build if packaging.version.Version(version) raises InvalidVersion
