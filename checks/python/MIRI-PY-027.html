MIRI-PY-027 — Security policy declared

support.security_policy present and resolvable

should severity LOW · 1 weight 1 requires network Lifecycle §3.1

Definition: standards/python/checks/MIRI-PY-027.yaml · view · raw

Violation
"support": { "status": "active", "security_policy": null } # a reporter's only visible channel is the public issue tracker
Compliant
"support": { "status": "active", "security_policy": "https://github.com/example/example-package/blob/main/SECURITY.md" } # resolves to a policy naming private vulnerability reporting

Why this matters

The security policy is where a reporter — human or agent — is told how to disclose the vulnerability they just found. Without a declared channel, reports default to the public issue tracker: the vulnerability is published before the maintainer has triaged it, which is full disclosure by accident. GitHub's private vulnerability reporting and the SECURITY.md convention exist precisely to prevent this; support.security_policy makes the channel discoverable from the installed wheel without a repository lookup.

Definition

Vulnerability and currency verdicts are computed externally by joining declared identity against advisory databases; a wheel that misdeclares identity or sources silently breaks that join. This check verifies: support.security_policy present and resolvable.

When it fires

  • support.security_policy is null or absent from lifecycle.json
  • The declared URL does not resolve (non-2xx response)

How to fix it

Link the project's SECURITY.md or equivalent policy.

  1. Publish a SECURITY.md naming a private reporting channel (GitHub private vulnerability reporting, or a monitored security@ address) and a response expectation
  2. Set support.security_policy to its stable URL in the Miri build configuration so every generated lifecycle.json carries it
