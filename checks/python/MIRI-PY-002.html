MIRI-PY-002 — Core metadata valid

METADATA parses as Core Metadata 2.x; name normalized

must severity HIGH · 4 weight 2 Core Metadata specificationPEP 639 (License-Expression)PEP 503

Definition: standards/python/checks/MIRI-PY-002.yaml · view · raw

Violation
METADATA: Metadata-Version: 2.1 Name: Example_SDK Version: 2.1.0 # normalizes to 'example-sdk'; consumers keyed on the normalized name # join this wheel to a different (or no) project
Compliant
METADATA: Metadata-Version: 2.1 Name: example-sdk Version: 2.1.0 # parses under packaging.metadata; Name equals its PEP 503 normalization

Why this matters

The Name and Version in METADATA are the identity every downstream join keys on: pip resolution, OSV advisory matching, and Miri's own purl-coherence check (MIRI-PY-019). PEP 503 defines a single canonical form — lowercase, with runs of -, _, and . collapsed to one - — precisely so that Example_SDK and example-sdk cannot be treated as distinct projects; Birsan's 2021 dependency-confusion research ran code inside more than 35 companies, Apple, Microsoft, and PayPal among them, by exploiting exactly the gap between the name a build referenced and the project an index resolved it to. A METADATA file that fails Core Metadata parsing removes the package from every automated pipeline at once.

Definition

Miri builds on the existing packaging standards rather than replacing them; a wheel that violates the baseline cannot carry trustworthy agent metadata. This check verifies: METADATA parses as Core Metadata 2.x; name normalized.

When it fires

  • METADATA fails to parse as Core Metadata 2.x (RFC 822 header syntax with a known 2.x Metadata-Version)
  • Name or Version is absent
  • Name differs from its PEP 503 normalization, i.e. from re.sub(r'[-_.]+', '-', name).lower()

How to fix it

Regenerate METADATA from pyproject.toml; normalize the name per PEP 503.

  1. Declare name and version in pyproject.toml's [project] table and let the backend emit METADATA rather than writing it
  2. Use the PEP 503 normalized form (example-sdk, never Example_SDK) everywhere the name appears — pyproject.toml, the purl in lifecycle.json, index URLs
  3. Gate releases on twine check dist/* and a parse with packaging.metadata in CI
  4. For metadata 2.4+, declare the license with the PEP 639 License-Expression (SPDX) field rather than the legacy free-text License field or License :: classifiers
