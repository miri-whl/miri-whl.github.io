MIRI-PY-017 — Error handling shown

Examples demonstrate the package's error/exception handling

should severity MINOR · 2 weight 2 Miri Wheel Ext. §7.2.2

Definition: standards/python/checks/MIRI-PY-017.yaml · view · raw

Violation
examples/quickstart.py: client = Client(api_key="YOUR_API_KEY") print(client.fetch("users")) # ConnectionError and AuthenticationError propagate uncaught; # sdk-manifest.json declares both, but no shipped example shows either
Compliant
examples/quickstart.py: try: print(client.fetch("users")) except example_sdk.AuthenticationError: sys.exit("invalid key: set EXAMPLE_SDK_API_KEY") # the canonical recovery path except example_sdk.ConnectionError as e: print(f"retrying once: {e}"); print(client.fetch("users"))

Why this matters

Miri Wheel Extensions §7.2.2 requires examples to include proper error handling because agents copy handling structure verbatim into generated integrations. sdk-manifest.json already declares the package's exception types and recovery guidance (Agent Metadata §4.1 error_handling), but a declaration no example exercises never reaches generated code: the agent reproduces the happy path it saw, and every downstream integration lets ConnectionError and its kin propagate uncaught.

Definition

Embedded examples are the primary learning path for agents; an example that does not run teaches a wrong lesson at machine speed. This check verifies: Examples demonstrate the package's error/exception handling.

When it fires

  • no example listed in AGENT_EXAMPLES.json contains a try/except (or equivalent guard) around a fallible call
  • none of the exception types declared in sdk-manifest.json error_handling or common_errors appears in any example's AST
  • the examples/ tree lacks an error-handling example even though sdk-manifest.json declares package exception types

How to fix it

Demonstrate the package's exception handling in each example.

  1. Wrap each example's fallible calls in try/except for the package's own exception types, demonstrating the recovery path (retry, re-authenticate, clean exit) rather than a bare pass
  2. Keep the demonstrated types aligned with sdk-manifest.json error_handling and common_errors so the two surfaces teach the same lesson
  3. Ship a dedicated examples/error_handling.py per §5.1 and reference it from the quickstart's related entries
