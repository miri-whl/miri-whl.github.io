MIRI-CLI-019 — Distribution declared

identity.distribution is open-source or private

must severity LOW · 1 weight 1 CLI Spec §3.1

Definition: standards/cli/checks/MIRI-CLI-019.yaml · view · raw

Violation
"identity": {"purl": "pkg:generic/acme/acme-cli@3.2.0"} # no distribution: a scanner cannot tell whether an empty public-OSV result means clean or merely unknown
Compliant
"identity": {"purl": "pkg:generic/acme/acme-cli@3.2.0?repository_url=https://releases.acme.example", "distribution": "private"}

Why this matters

The declaration selects which security defaults apply. OSV's /v1/query returns an empty result both when a package is known and clean and when the database has simply never heard of the name — so for a private CLI an empty public-OSV response is silence, not clearance, and spec §4 forbids treating it as "not vulnerable" unless public OSV is explicitly listed. A scanner can only apply that rule if the artifact states which population it belongs to; an undeclared distribution defaults private tools into a false clean bill.

Definition

A CLI must be able to say who it is and what it offers, so scanners can join it against advisory databases and agents can trust the surface they see. This check verifies: identity.distribution is open-source or private.

When it fires

  • identity.distribution is absent from --describe
  • Its value is anything other than the exact strings "open-source" or "private"

How to fix it

Declare open-source or private.

  1. Declare distribution in the build-time identity block; the value is structural, not per-install, so it belongs with the version and purl constants
  2. For "private", pair the declaration with an osv-internal or osv-local advisory source (§8.2) so the §4 empty-result rule has an authoritative source to defer to
