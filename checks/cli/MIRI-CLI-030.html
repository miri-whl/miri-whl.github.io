MIRI-CLI-030 — Changelog coverage

Output covers added/removed/deprecated surfaces, schema bumps, exit-code changes

must severity MEDIUM · 3 weight 1 conditional requires previous-release CLI Spec §5.2

Definition: standards/cli/checks/MIRI-CLI-030.yaml · view · raw

Violation
# 3.2.0 bumped schema_version 1 -> 2 and changed exit code 3's meaning $ acme-cli changelog --since 3.1.0 --json {"schema_version": "1", "releases": [{"version": "3.2.0", "added": ["--format"]}]} # consumer re-learns the flags, then breaks on the unreported payload shape
Compliant
{"schema_version": "1", "releases": [{"version": "3.2.0", "added": ["--format"], "schema_version_change": {"from": "1", "to": "2"}, "exit_code_changes": [{"code": 3, "was": "not found", "now": "permission denied"}]}]}

Why this matters

§5.2 makes five categories normative — added, removed, and deprecated surfaces, schema_version bumps, and exit-code meaning changes — because these are precisely the change classes that break machine consumers. A changelog that reports new flags but omits the wire-schema bump answers "what moved" incompletely: the consumer updates its command model and still breaks on the payload shape that went unreported, restoring the exact blind spot the command exists to remove. Ecosystem prior art (towncrier-style CI bots) only enforces that *an entry exists*, never that it is complete (§6.3).

Definition

An agent that has been away for three releases must be able to ask what moved; update state must be queryable, passive, and honest offline. This check verifies: Output covers added/removed/deprecated surfaces, schema bumps, exit-code changes.

When it fires

  • diffing the previous release's --describe against the current one yields an added, removed, or deprecated surface absent from the changelog --since <previous> output
  • a schema_version transition or an exit-code meaning change occurred between the releases but does not appear in the output
  • one of the five normative §5.2 categories has no representation in the output shape at all

How to fix it

Cover added/removed/deprecated surfaces, schema bumps, and exit-code changes.

  1. Generate the changelog mechanically from the schema-as-data diff between releases (§2.3), so surface changes cannot be omitted by hand
  2. Include schema_version transitions and the exit-code table in the diffed struct, not just flags and subcommands
  3. Add a release-CI fixture: cut a test release that removes a flag and bumps schema_version, and assert both appear in changelog --since
