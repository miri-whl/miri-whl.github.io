MIRI-CLI-011 — Clean payload channel

No ANSI codes, prose, or warnings mixed into stdout JSON

must severity HIGH · 4 weight 2 CLI Spec §2.5

Definition: standards/cli/checks/MIRI-CLI-011.yaml · view · raw

Violation
$ tool list --json WARNING: --legacy-ids is deprecated, use --ids {"schema_version": "1", "items": []} $ tool list --json | jq . jq: error (at <stdin>:1): Invalid literal at line 1, column 8 # every consumer broke the day the warning shipped
Compliant
$ tool list --json 2>warnings.txt {"schema_version": "1", "items": []} $ cat warnings.txt WARNING: --legacy-ids is deprecated, use --ids # payload parses; the notice survives on its own channel

Why this matters

CLI Spec §2.5 reserves stdout for the JSON payload and sends all warnings to stderr, because the channels fail differently: a warning on stderr is ignorable, but one stray notice printed into stdout makes the document unparseable — jq aborts with Invalid literal, and every downstream consumer fails simultaneously the day the notice ships, not the day the schema changes. This is the highest-blast-radius mistake available to a machine-output CLI precisely because the trigger is routine (a deprecation notice, an update banner, a stray print in a logging path) while the failure is total.

Definition

Agents parse stdout; anything unstructured, inconsistent, or polluted forces guesswork and burns recovery turns. This check verifies: No ANSI codes, prose, or warnings mixed into stdout JSON.

When it fires

  • stdout of any JSON-mode invocation fails a strict JSON parse (jq -e . non-zero)
  • Prose lines — update banners, deprecation notices, progress text — precede, follow, or interleave the JSON document on stdout
  • ESC bytes (0x1b) appear inside stdout in JSON mode

How to fix it

Keep stdout pure JSON; warnings go to stderr.

  1. Route every diagnostic through a channel that writes to stderr; audit logging configuration — many logging frameworks default handlers to stdout
  2. In JSON mode, write stdout exactly once, from the shared response envelope (one serialized document, then exit)
  3. Keep decoration out of JSON mode entirely, independent of TTY state (see MIRI-CLI-005)
  4. Parse your own stdout in CI: for every command, <cmd> --json | jq -e . >/dev/null and assert the byte stream contains no 0x1b
