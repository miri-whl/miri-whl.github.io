MIRI-CLI-002 — Conforming --help

--help prints to stdout, exits 0, never pages or blocks

must severity HIGH · 4 weight 2 GNU Coding Standards §4.7

Definition: standards/cli/checks/MIRI-CLI-002.yaml · view · raw

Violation
$ tool log --help (man page opens in less; with stdin closed the process blocks until the CI job timeout kills it) $ tool --help >/dev/null; echo $? 1
Compliant
$ tool deploy --help | cat Usage: tool deploy [OPTIONS] TARGET --json emit machine-readable output --yes skip confirmation $ echo $? 0

Why this matters

GNU Coding Standards §4.7 requires --help to print to stdout and exit successfully; help is also how an agent learns a CLI at runtime, so it must work precisely in the non-interactive context where agents live. The canonical counterexample is git, whose git log --help opens the man page in a pager — in CI or an agent harness that blocks on a dead terminal, varies with PAGER, and emits terminal control codes, which is why --no-pager and core.pager cat are standing CI folklore. Help on stderr or with a non-zero exit is equally corrosive: every wrapper that checks the exit code reads a successful help request as a failure.

Definition

Agents drive CLIs through the same conventions humans and scripts rely on; a tool that breaks them is invisible or hangs silently in a non-interactive context. This check verifies: --help prints to stdout, exits 0, never pages or blocks.

When it fires

  • With stdin closed and stdout redirected, <cli> --help spawns a pager or the process blocks on a read
  • Help text is written to stderr instead of stdout
  • <cli> --help exits non-zero, or exits 0 with empty stdout

How to fix it

Print help to stdout, exit 0, never invoke a pager.

  1. Print help to stdout and exit 0, ignoring other options once --help is seen (GNU §4.7)
  2. Never spawn $PAGER, less, or man from the help path; if paging is offered interactively, gate it on isatty(stdout)
  3. Add a CI assertion: <cli> --help </dev/null >help.txt 2>err.txt completes within a short timeout, exits 0, help.txt is non-empty, err.txt is empty
