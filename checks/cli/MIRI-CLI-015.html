MIRI-CLI-015 — --describe implemented

Machine-readable introspection output exists and is valid JSON

must severity CRITICAL · 5 weight 3 CLI Spec §3

Definition: standards/cli/checks/MIRI-CLI-015.yaml · view · raw

Violation
$ acme --describe Error: unknown flag: --describe Usage: acme <command> [flags] $ echo $? 2
Compliant
$ acme --describe {"schema_version": "1", "identity": {"purl": "pkg:npm/acme-cli@3.2.0", "version": "3.2.0", "distribution": "open-source"}, "support": {"status": "active"}, "advisory_sources": [{"type": "osv", "ecosystem": "npm", "url": "https://api.osv.dev/v1/query"}], "commands": [{"name": "deploy", "flags": [{"name": "--output"}]}]}

Why this matters

--describe is the substrate for every identity, support, and lifecycle check that follows: without it the CLI has no purl to join against OSV, no support status, and no per-flag lifecycle — the agent is back to frozen training data and help parsing, which is brittle by construction (on macOS, git log --help routes into a pager that blocks non-interactive contexts). Go's embedded buildinfo is the existence proof that binary self-identification works: because go version -m can read any Go binary's module list, govulncheck, osv-scanner, and Trivy scan Go CLIs with zero author effort, while every other standalone binary is left to CPE guessing. --describe extends that legibility to CLIs in any language.

Definition

A CLI must be able to say who it is and what it offers, so scanners can join it against advisory databases and agents can trust the surface they see. This check verifies: Machine-readable introspection output exists and is valid JSON.

When it fires

  • The binary accepts no --describe (or documented equivalent introspection command)
  • Invoking it exits non-zero or prints a usage/unknown-flag error
  • Its stdout does not parse as a single JSON document — prose banners, ANSI codes, or log lines are mixed in

How to fix it

Implement --describe emitting the identity, support, and surface data as JSON.

  1. Implement --describe emitting one JSON document to stdout with exit code 0
  2. Populate it with identity, support, advisory_sources, and the full command/flag surface, generated from the same schema-as-data structure as --help (§2.3) — never by parsing the CLI's own help text
  3. Keep every human-facing notice on stderr so the document stays parseable (§2.5)
  4. Gate releases in CI on parse and schema validation: acme --describe | python3 -m json.tool > /dev/null
