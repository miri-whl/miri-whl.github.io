MIRI-CLI-009 — One output flag

The same flag (e.g. --json) selects it on every command — no per-command variants

must severity MEDIUM · 3 weight 2 Landscape §2.3 (Chow)

Definition: standards/cli/checks/MIRI-CLI-009.yaml · view · raw

Violation
$ tool list --json {"items": []} $ tool status --json error: unknown flag: --json (did you mean --output json?) # same tool, two grammars for the same concept
Compliant
$ tool list --json | jq -e .schema_version "1" $ tool status --json | jq -e .schema_version "1" # one flag, inherited by every command from the root parser

Why this matters

The ecosystem's own fragmentation shows the cost: kubectl selects JSON with -o json, docker with --format json, and gh with --json <fields> — three grammars for one concept, so nothing an agent learns on one tool transfers to the next. Inside a single CLI the same inconsistency is strictly worse (Chow, landscape §2.3): an agent that learned --json on one command constructs it on the next, gets unknown flag, and from then on treats the whole tool as unreliable, re-verifying every invocation it should have been able to generalize.

Definition

Agents parse stdout; anything unstructured, inconsistent, or polluted forces guesswork and burns recovery turns. This check verifies: The same flag (e.g. --json) selects it on every command — no per-command variants.

When it fires

  • Different commands select machine output with different flags (--json on some, --output json or --format=json on others)
  • The root-level output flag exists but is rejected by some subcommands
  • --describe records per-command output-flag names that differ from the root flag

How to fix it

Pick one output flag and use it everywhere.

  1. Define the output flag once at the root parser and inherit it everywhere: cobra PersistentFlags(), clap global = true, argparse via a shared parent parser
  2. Migrate stragglers by aliasing the legacy per-command spelling to the root flag, marking the alias with a lifecycle block (deprecated_since, replacement) per CLI Spec §6 until removal
  3. Assert uniformity in CI: every command in --describe accepts the root output flag and lists no variant spellings
