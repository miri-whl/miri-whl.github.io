MIRI-CLI-012 — Deterministic ordering

Same inputs produce identically ordered output

should severity MINOR · 2 weight 2 Landscape §2.1 P03

Definition: standards/cli/checks/MIRI-CLI-012.yaml · view · raw

Violation
$ acme list --json | jq -c '[.items[].name]' ["web","auth","db"] $ acme list --json | jq -c '[.items[].name]' ["db","web","auth"] # same state, map-iteration order leaked into output
Compliant
$ acme list --json | jq -c '[.items[].name]' ["auth","db","web"] $ acme list --json | jq -c '[.items[].name]' ["auth","db","web"] # collections sorted by name before emission

Why this matters

Agent-First CLI principle 03 (deterministic ordering) exists because the commonest container types are nondeterministic by construction: Go's runtime deliberately randomizes map iteration order, Python randomizes string hashing per process (PYTHONHASHSEED), and readdir() returns filesystem-dependent order — so a CLI that serializes any of these directly emits differently ordered output for identical state. Every consumer that compares runs then breaks: caches miss, diffs show phantom changes, and an agent comparing before/after output infers a state change that never happened. The reproducible-builds project documents the same failure class for build outputs and prescribes the same fix: sort by a stable key before emission.

Definition

Agents parse stdout; anything unstructured, inconsistent, or polluted forces guesswork and burns recovery turns. This check verifies: Same inputs produce identically ordered output.

When it fires

  • Two invocations of the same command with identical inputs and state emit the same elements in different order
  • Array order in JSON output tracks map/hash iteration or directory-read order rather than a documented sort key
  • Output ordering changes with the locale environment (LC_ALL, LC_COLLATE) for identical inputs

How to fix it

Sort output deterministically.

  1. Sort every collection by a stable, documented key immediately before serialization (e.g. name, then version) — never emit insertion or iteration order
  2. Sort bytewise or with an explicit collation rather than the ambient locale; pin LC_ALL=C in tests
  3. Serialize maps with sorted keys (json.dumps(sort_keys=True) in Python; Go's encoding/json already sorts map keys)
  4. Add a CI determinism test: run the command twice — including under different PYTHONHASHSEED or locale values — and diff the outputs
