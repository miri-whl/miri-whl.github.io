MIRI-CLI-014 — Recoverable errors

Errors carry retryable and suggestions

should severity MINOR · 2 weight 2 CLI Spec §2.6

Definition: standards/cli/checks/MIRI-CLI-014.yaml · view · raw

Violation
{"schema_version": "1", "ok": false, "error": {"code": "AUTH_EXPIRED"}} # the agent cannot tell whether to retry as-is, re-authenticate, or abort
Compliant
{"schema_version": "1", "ok": false, "error": {"code": "AUTH_EXPIRED", "retryable": false, "suggestions": ["run acme login --sso, then re-issue the command"]}}

Why this matters

A bare error leaves an agent its only fallback strategy — blind retry — which loops on permanent failures and abandons transient ones. The retryable boolean is the classification that makes AWS SDK retry machinery work (throttling errors are retried with backoff, validation errors are not), and suggestions follows the shipped desk pattern (landscape §2.3): dynamically generated next actions that convert a dead end into a one-turn recovery, such as naming the login command on an auth failure or the replacement surface on a removal (§6).

Definition

Agents parse stdout; anything unstructured, inconsistent, or polluted forces guesswork and burns recovery turns. This check verifies: Errors carry retryable and suggestions.

When it fires

  • Error envelopes carry no retryable boolean
  • Transient failures (timeout, rate limit) and permanent ones (validation, auth, removed flag) are indistinguishable in the payload
  • suggestions is absent, empty, or static boilerplate not derived from the failing context

How to fix it

Add retryable and suggestions to the error object.

  1. Extend the §6 error envelope with retryable and suggestions[]
  2. Classify the error taxonomy once: network timeouts and rate limits set retryable: true; validation, authentication, and removed-surface errors set retryable: false
  3. Generate suggestions from the failing context — the nearest-match flag for a typo, the exact login command for AUTH_EXPIRED, the lifecycle.replacement value for FLAG_REMOVED
  4. Document both fields in the wire schema so consumers can rely on their presence
