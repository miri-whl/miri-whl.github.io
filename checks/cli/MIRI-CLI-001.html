MIRI-CLI-001 — POSIX option syntax

- short options, -- terminator, options-before-operands accepted

must severity MEDIUM · 3 weight 2 POSIX XBD §12.2

Definition: standards/cli/checks/MIRI-CLI-001.yaml · view · raw

Violation
$ tool -ab target/ # -a and -b are both valid no-arg flags error: unknown option '-ab' $ tool delete -- --force # operand named '--force' error: unknown option '--force'
Compliant
$ tool -ab target/ # equivalent to: tool -a -b target/ $ tool -o out.json target/ # and: tool -oout.json target/ $ tool delete -- --force # deletes the entry literally named '--force' $ echo $? 0

Why this matters

POSIX XBD §12.2 is the one option grammar every shell user, script, and agent already knows: Guideline 5 permits grouping no-argument options behind a single -, Guideline 9 has options precede operands, and Guideline 10 reserves -- as the end-of-options delimiter. An agent composes invocations from that shared grammar, not from the tool's private one, so a parser that rejects -ab bundling or ignores -- makes conventionally correct commands fail — and a missing -- terminator makes operands that begin with - (a file literally named -rf, a branch named --force) impossible to pass safely at all.

Definition

Agents drive CLIs through the same conventions humans and scripts rely on; a tool that breaks them is invisible or hangs silently in a non-interactive context. This check verifies: - short options, -- terminator, options-before-operands accepted.

When it fires

  • A grouped invocation -ab is rejected while -a -b is accepted, for options taking no argument
  • An operand placed after -- is parsed as an option (or -- itself is reported as an unknown option)
  • -o value and -ovalue are not treated as equivalent for an option that takes an argument
  • Options appearing before operands are rejected or silently treated as operands

How to fix it

Follow POSIX XBD §12.2 option syntax, including the -- terminator.

  1. Replace any hand-rolled argv loop with a getopt-family parser that implements POSIX XBD §12.2 (argparse, clap, cobra/pflag, getopt_long)
  2. Add parser conformance tests covering the three §12.2 trouble spots: -ab bundling, the -- terminator, and -o value/-ovalue equivalence
  3. If the tool must deviate (single-dash long options, ordered operands), declare the deviation in --describe rather than leaving it discoverable only by failure
