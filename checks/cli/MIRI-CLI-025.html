MIRI-CLI-025 — check-update implemented

check-update --json returns the specified shape

must severity HIGH · 4 weight 4 CLI Spec §5.1

Definition: standards/cli/checks/MIRI-CLI-025.yaml · view · raw

Violation
$ acme-cli check-update --json error: unknown command "check-update" for "acme-cli" $ echo $? 1
Compliant
$ acme-cli check-update --json {"schema_version": "1", "current": "3.2.0", "latest": "3.4.1", "update_available": true, "urgency": "security", "advisories": ["ACME-2026-0007"], "manifest": "https://releases.acme.example/acme-cli/manifest.json", "install_hint": "brew upgrade acme-cli"}

Why this matters

No standard answers "is there a newer version of this binary": update-notifier polls the npm registry from a detached child process, Azure CLI ships its own az upgrade, and Homebrew answers only for tools it installed — every vendor a homegrown notifier against a homegrown endpoint that no agent or auditor can discover. check-update --json replaces that zoo with one declared primitive whose manifest field names the endpoint consulted, making the check itself auditable. Without it, an agent whose knowledge froze at 3.2.0 has no standard way to learn that 3.4.1 exists, let alone that the gap is a security release.

Definition

An agent that has been away for three releases must be able to ask what moved; update state must be queryable, passive, and honest offline. This check verifies: check-update --json returns the specified shape.

When it fires

  • <cli> check-update --json is unrecognized or exits non-zero in a healthy online environment
  • stdout is not a single JSON document, or lacks any of schema_version, current, latest, update_available, urgency
  • urgency is outside {none, routine, recommended, security}, or current disagrees with the binary's --version

How to fix it

Implement check-update --json per CLI Spec §5.1.

  1. Implement check-update --json returning the §5.1 shape, derived from the same schema-as-data source as --help and --describe (§2.3)
  2. Point it at a declared manifest: the registry API when registry-distributed (§7.1), the forge's releases API or a static JSON file adjacent to the artifacts for direct or private distribution (§8.3)
  3. Populate manifest with the endpoint consulted and install_hint with the channel-appropriate upgrade command
  4. Keep the output JSON-on-stdout, exit 0; any diagnostics go to stderr (§2.5)
