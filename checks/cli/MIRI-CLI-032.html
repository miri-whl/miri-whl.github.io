MIRI-CLI-032 — Two-phase fields

deprecated_since and removed_in/replacement populated

must severity MINOR · 2 weight 2 CLI Spec §6.1RFC 9745RFC 8594

Definition: standards/cli/checks/MIRI-CLI-032.yaml · view · raw

Violation
{"name": "--export", "lifecycle": {"status": "deprecated", "deprecated_since": "1.14.0"}} # no removed_in, no replacement: consumers know to leave, not when or where to go
Compliant
{"name": "--export", "lifecycle": {"status": "deprecated", "deprecated_since": "1.14.0", "removed_in": "1.18.0", "replacement": "--output archive"}}

Why this matters

The two-phase shape carries a citation trail rather than invention (§6.1): deprecated_since is the CLI analogue of RFC 9745's Deprecation header marking that the phase has begun, removed_in of RFC 8594's Sunset header marking when the surface stops working, and replacement follows PEP 702's @deprecated, GraphQL's @deprecated(reason:), and Java's @Deprecated(since, forRemoval). A block carrying only deprecated_since is half a contract: consumers know to leave, but neither when the door closes nor where to go — so migration can be neither scheduled nor automated.

Definition

Deprecation markers, the changelog, and actual removals must agree; a removed flag that answers with a dead-end error strands every consumer working from stale knowledge. This check verifies: deprecated_since and removed_in/replacement populated.

When it fires

  • a lifecycle block with status: "deprecated" lacks deprecated_since
  • neither removed_in nor replacement is populated on a deprecated surface
  • populated fields are unusable — removed_in is not a valid version, or replacement is an empty string

How to fix it

Populate the two-phase fields (RFC 9745/8594 shape).

  1. Populate deprecated_since with the release that introduced the deprecation
  2. Populate removed_in honoring the §7.3 grace period (at least one minor release in which the surface still functions) and replacement with the successor surface — which must exist in the current --describe (§6.3-3)
  3. Add a migration URL when the replacement alone does not capture the behavioral change
  4. Validate lifecycle blocks against the introspection schema in release CI so incomplete blocks fail before shipping
