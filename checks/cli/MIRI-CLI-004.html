MIRI-CLI-004 — Per-subcommand help

<cli> <sub> --help works for every subcommand

should severity MINOR · 2 weight 1 clig.dev

Definition: standards/cli/checks/MIRI-CLI-004.yaml · view · raw

Violation
$ tool deploy --help error: unknown flag: --help $ tool config set --help Usage: tool [OPTIONS] COMMAND # root help; nothing about 'config set'
Compliant
$ tool deploy --help Usage: tool deploy [OPTIONS] TARGET --strategy <rolling|blue-green> --dry-run simulate without writing $ echo $? 0

Why this matters

Agents discover a command tree incrementally, one --help at a time (clig.dev's per-subcommand help recommendation exists for exactly this walk). A subcommand without help is a dead end that forces the agent to guess flags against the live tool — and for a mutating subcommand, guessing means learning the interface by side effect. Because help must derive from the same schema as the definition itself (CLI Spec §2.3), a missing subcommand help is also a symptom that the surface is hand-maintained and already drifting.

Definition

Agents drive CLIs through the same conventions humans and scripts rely on; a tool that breaks them is invisible or hangs silently in a non-interactive context. This check verifies: <cli> <sub> --help works for every subcommand.

When it fires

  • For any subcommand listed in --describe or the root help, <cli> <sub> --help exits non-zero or reports an unknown flag
  • <cli> <sub> --help prints the root usage text instead of usage specific to <sub>
  • <cli> <sub> --help exits 0 with empty or placeholder output

How to fix it

Wire --help on every subcommand.

  1. Generate per-subcommand help from the same schema-as-data structure that defines the subcommand (CLI Spec §2.3); framework parsers (argparse subparsers, cobra, clap) do this when every subcommand is registered with its own description and flag set
  2. Add a CI loop: enumerate subcommands from --describe and assert <cli> <sub> --help exits 0 with non-empty, subcommand-specific stdout
  3. For nested trees, verify the walk at every depth (<cli> <sub> <subsub> --help), not just the first level
