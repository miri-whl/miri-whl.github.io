MIRI-CONSUMER-010 — Settles symbol existence with `resolve`, not index membership

Settles symbol existence with resolve, not index membership

must severity HIGH · 4 weight 8 Discovery Contract §3.6Consumption Map §3.2

Definition: standards/consumption/checks/MIRI-CONSUMER-010.yaml · view · raw

Violation
from greet_adversarial import GreeterPro client = GreeterPro(api_key=..., template=...) # GreeterPro appears in api_index and does not exist
Compliant
GreeterPro is listed in the package's api_index but resolve reports it is not defined in the installed source. I have not emitted a call to it.

Why this matters

api_index is the publisher's description of the surface, and the adversarial fixture demonstrates the gap: it claims two symbols that do not exist anywhere in the source. A consumer that generates code from the index sends a caller straight to AttributeError, which is the anti-hallucination failure the standard exists to end. Existence comes from the source; the index only routes.

Definition

Before emitting a call, a consumer must confirm the symbol exists. This check verifies it uses the existence operation rather than treating a publisher-authored index as proof.

When it fires

  • Driven against adversarial, the consumer emits a call to a symbol present in api_index but absent from the source
  • The consumer presents a call as verified without a confirming resolve result

How to fix it

Call resolve for every symbol before emitting a call to it

  1. Call resolve for every symbol before emitting a call to it
  2. Treat api-index as routing only; never as an existence proof
