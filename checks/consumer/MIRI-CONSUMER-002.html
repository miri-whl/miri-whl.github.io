MIRI-CONSUMER-002 — Never synthesizes content for an absent document

Never synthesizes content for an absent document

must severity CRITICAL · 5 weight 8 Consumption Map §4

Definition: standards/consumption/checks/MIRI-CONSUMER-002.yaml · view · raw

Violation
greet_bare quickstart: from greet_bare import Greeter Greeter().greet("Ada") (no examples were shipped; this was generated)
Compliant
greet_bare ships no usage examples. I can suggest an integration, but it would be mine, not the package's, and nothing verified it runs.

Why this matters

Synthesis is the failure that makes absence worse than useless: an agent that fabricates a lifecycle status or an example is more dangerous than one that says nothing, because the fabrication carries the standard's implied authority. The bare fixture exists to catch exactly this — identical source, no metadata, so anything the consumer attributes to the package is invented.

Definition

When a document is absent, a consumer must not invent its content. This check verifies the consumer does not present generated or recalled material as though the package had shipped it.

When it fires

  • Driven against bare, the consumer presents lifecycle, usage, or API content attributed to the package
  • The consumer's output does not distinguish what it read from what it inferred
  • A skipped read-step is reported without naming all three of the task and step (3.3 step 2), and a reason from the fixed set absent / unavailable-vehicle / error / not-applicable. A report missing the reason leaves a caller unable to tell a package fact from an attempt fact, which is the distinction the set exists to draw

How to fix it

On an absent response, emit the absence and stop; do not fall back to model priors while retaining attribution

  1. On an absent response, emit the absence and stop; do not fall back to model priors while retaining attribution
  2. Where the consumer does offer its own suggestion, label it as the consumer's, not the package's
