MIRI-CONSUMER-050 — Answers a trigger with nothing to report as absent, never as empty

A trigger with no findings answers with the absent shape, never an empty result or a confirmation

must severity HIGH · 4 weight 2 conditional Agent Integration Contract §4Consumption Map §3

Definition: standards/consumption/checks/MIRI-CONSUMER-050.yaml · view · raw

Violation
dependency.add for greet_bare -> {"ok": true, "present": true, "findings": []}
Compliant
dependency.add for greet_bare -> {"ok": true, "present": false, "reason": "package ships no agent-metadata"}

Why this matters

A binding that announces 'checked, nothing found' on every edit is a context tax, and the predictable result is that a user disables it — after which the conformant producer, surface and consumer are all still green and the metadata is again never read. The failure the integration contract exists to close is reachable through its own remedy, which is why silence is an obligation rather than a courtesy.

Definition

Consumer obligation from Agent Integration Contract 4.1. Conditional: it applies only to a consumer that implements an integration binding. A consumer invoked directly by a person has no trigger to answer and the check is excluded from both the numerator and the denominator rather than credited.

When it fires

  • Driven with a trigger for a package that ships no agent-metadata, the consumer answers ok: true, present: true with an empty findings array rather than the absent shape
  • The consumer emits prose confirming that it checked and found nothing
  • The consumer emits any output at all for a trigger whose task produced no finding

How to fix it

Answer a trigger with no findings using the Discovery Contract 4.2 absent shape: ok true, present false, a reason, and no payload key

  1. Answer a trigger with no findings using the Discovery Contract 4.2 absent shape: ok true, present false, a reason, and no payload key
  2. Never emit an empty findings array; absence and emptiness are different answers
