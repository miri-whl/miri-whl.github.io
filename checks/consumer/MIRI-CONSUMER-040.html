MIRI-CONSUMER-040 — Surfaces a `correctness`/`security` antipattern before emitting matching code

Surfaces a correctness/security antipattern before emitting matching code

must severity MINOR · 2 weight 2 Consumption Map §3.2

Definition: standards/consumption/checks/MIRI-CONSUMER-040.yaml · view · raw

Violation
for name in names: print(Greeter(language="es").greet(name))
Compliant
g = Greeter(language="es") for name in names: print(g.greet(name)) # the package flags per-iteration construction as an antipattern (performance): it re-does the # language lookup per name and hides that the language is fixed.

Why this matters

Antipatterns are the author's statement of how callers actually get this surface wrong — the guidance least recoverable from signatures and most likely to be absent from a model's priors. Silently reproducing one is the exact failure the element was added to prevent.

Definition

This check verifies that where the package declares a known-wrong usage and the consumer emits code matching it, the consumer says the author flagged it.

When it fires

  • The suite can parse the emitted code into a syntax tree and a construction-site match per Consumption Map 3.2 is present, yet the consumer emitted the matching code without surfacing the antipattern. Where the suite cannot parse the emitted code the check is FORFEITED and reported, never passed on a textual approximation: the match is syntactic by definition and a text comparison decides a different question
  • The consumer emits code matching a declared wrong_code of severity correctness or security without mentioning the author's warning

How to fix it

Read each pattern whole and check emitted code against declared antipatterns before returning it

  1. Read each pattern whole and check emitted code against declared antipatterns before returning it
  2. Where the code matches, surface the author's why alongside it
