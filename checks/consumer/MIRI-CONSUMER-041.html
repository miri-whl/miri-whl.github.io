MIRI-CONSUMER-041 — Never presents a synthesized mock as the package's supported test double

Never presents a synthesized mock as the package's supported test double

must severity MINOR · 2 weight 1 Consumption Map §3.6

Definition: standards/consumption/checks/MIRI-CONSUMER-041.yaml · view · raw

Violation
Use the package's official test double: from unittest.mock import MagicMock client = MagicMock()
Compliant
This package declares no supported test doubles. Below is a mock I constructed — it is mine, not the package's, and nothing guarantees it matches real behavior.

Why this matters

A test built on a fake the package does not support drifts silently from the real behavior, and the drift surfaces as a passing test over broken code. Only supported_test_doubles entries carry the author's fidelity commitment.

Definition

This check verifies the consumer distinguishes doubles the package ships from ones the consumer invented.

When it fires

  • The consumer presents a mock absent from supported_test_doubles as the package's official test double

How to fix it

Use only declared doubles when claiming support; label anything else as the consumer's own construction
