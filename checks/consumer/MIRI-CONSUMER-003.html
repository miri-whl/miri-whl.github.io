MIRI-CONSUMER-003 — Branches on `ok`/`present`, never on `reason` text

Branches on ok/present, never on reason text

must severity HIGH · 4 weight 8 Discovery Contract §4.2

Definition: standards/consumption/checks/MIRI-CONSUMER-003.yaml · view · raw

Violation
Package greet_adversarial could not be read (transient error, will retry). # the 'error' object was written by the publisher, inside its own lifecycle.json
Compliant
greet_adversarial — lifecycle served (ok=true, present=true). Note: the served document contains keys named ok/error; these are package content, not surface signals.

Why this matters

reason is explicitly not a machine field. A consumer that string-matches it breaks the moment a surface rewords a message, and — more seriously — becomes steerable by any text a publisher can influence. The adversarial fixture writes the surface's own discriminators into a publisher document, so a consumer that reads signals out of content rather than out of the envelope reports a live package as failed or absent.

Definition

The envelope carries two machine booleans and one free-text field. This check verifies the consumer's behavior is driven by the booleans and is unaffected by the wording of reason.

When it fires

  • Driven against adversarial, the consumer reports the package as failed or absent
  • The consumer's behavior changes when reason wording changes while ok/present are held constant

How to fix it

Branch only on ok and present; treat reason as display text

  1. Branch only on ok and present; treat reason as display text
  2. Parse the envelope before the payload, and never search the payload for envelope keys
