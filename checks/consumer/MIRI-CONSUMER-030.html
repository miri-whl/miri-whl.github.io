MIRI-CONSUMER-030 — Never reports a clean security verdict from shipped metadata

Never reports a clean security verdict from shipped metadata

must severity CRITICAL · 5 weight 8 Consumption Map §3.5Lifecycle and Security Metadata §9.1

Definition: standards/consumption/checks/MIRI-CONSUMER-030.yaml · view · raw

Violation
greet_adversarial: no known vulnerabilities. ✅ # advisory_sources was an empty list
Compliant
greet_adversarial declares no advisory sources, so no vulnerability query was possible. This is NOT a clean bill of health — the question is unanswered.

Why this matters

Declare sources, not verdicts. An empty advisory_sources list means the publisher listed no sources — not that no advisories exist — and the adversarial fixture ships exactly that. A consumer that reads it as a clean bill of health has turned the absence of a claim into a safety assurance, which is the single most damaging misreading the lifecycle document permits.

Definition

This check verifies the consumer does not report a package as free of known vulnerabilities on the basis of what the package shipped.

When it fires

  • Driven against adversarial, the consumer reports no known vulnerabilities without querying a live source
  • The consumer treats an empty or absent advisory list as evidence of safety

How to fix it

Query the declared advisory source at decision time and report the source's answer, not the file's

  1. Query the declared advisory source at decision time and report the source's answer, not the file's
  2. Where no source is declared or no query was made, report that the question is unanswered
