MIRI-SURFACE-040 — Derives `purl` from the installed distribution; never reads it from a document

Derives purl from the installed distribution; never reads it from a document

must severity CRITICAL · 5 weight 6 Discovery Contract

Definition: standards/consumption/checks/MIRI-SURFACE-040.yaml · view · raw

Violation
purl = doc["identity"]["purl"] # publisher-authored
Compliant
purl = f"pkg:pypi/{dist.metadata['Name']}@{dist.version}" # surface-derived

Why this matters

purl is the input to a per-namespace trust policy, which makes it a security decision — and the one field in the envelope a publisher must not control. If the surface reads identity.purl out of lifecycle.json, a package declaring pkg:pypi/requests@2.31.0 inherits requests' trust tier by simply saying so, forging a signal inside the namespace §4 claims is un-forgeable.

Definition

Surface obligation from the Discovery Contract. This check verifies: Derives purl from the installed distribution; never reads it from a document.

When it fires

  • The envelope purl is read from a served document rather than derived from the installed distribution
  • A disagreement between the derived value and identity.purl is resolved in the document's favor
  • purl is emitted on a response whose subject package did not resolve

How to fix it

Derive purl from the installed distribution's own recorded name and version

  1. Derive purl from the installed distribution's own recorded name and version
  2. Where identity.purl disagrees, serve the derived value and signal the mismatch as a tampering indicator
  3. Omit purl entirely for PACKAGE_NOT_INSTALLED, AMBIGUOUS_PACKAGE and NOT_DISCOVERABLE
