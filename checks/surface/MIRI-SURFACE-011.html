MIRI-SURFACE-011 — Reports failure as `ok: false` with a coded `error` object

Reports failure as ok: false with a coded error object

must severity HIGH · 4 weight 7 Discovery Contract

Definition: standards/consumption/checks/MIRI-SURFACE-011.yaml · view · raw

Violation
{"schema_version": "1", "ok": false, "error": "package not found"}
Compliant
{"schema_version": "1", "ok": false, "package": "nope", "error": {"code": "PACKAGE_NOT_INSTALLED", "retryable": false}}

Why this matters

A consumer branches on error.code to decide whether to retry, re-ask, or stop. Prose alone forces string matching, which breaks on rewording and cannot be tested. The contract reuses the CLI §2.6 envelope so one error vocabulary spans the standard.

Definition

Surface obligation from the Discovery Contract. This check verifies: Reports failure as ok: false with a coded error object.

When it fires

  • A failure returns without ok: false, or without a top-level error object
  • error.code is absent, or is not one of the codes defined in §4.3
  • error.retryable is absent, or is true for a failure the identical call can never resolve

How to fix it

Return ok: false with error: {code, retryable} using the §4.3 codes

  1. Return ok: false with error: {code, retryable} using the §4.3 codes
  2. Set retryable true only for transient conditions — never for a request the caller must change
