MIRI-SURFACE-051 — Carries absence and error as tool results, never as protocol errors

Carries absence and error as tool results, never as protocol errors

must severity MEDIUM · 3 weight 3 Discovery Contract

Definition: standards/consumption/checks/MIRI-SURFACE-051.yaml · view · raw

Violation
{"jsonrpc": "2.0", "error": {"code": -32602, "message": "no lifecycle.json"}}
Compliant
{"content": [{"type": "text", "text": "{\"schema_version\":\"1\",\"ok\":true,\"present\":false,…}"}]}

Why this matters

Absence and a coded error are both *served answers* — the surface did its job and is reporting a fact. Sending either as a JSON-RPC protocol error puts them in a channel that carries no envelope, so the consumer loses present, purl, and the error code, and must infer from transport machinery what the contract took care to state explicitly.

Definition

Surface obligation from the Discovery Contract. This check verifies: Carries absence and error as tool results, never as protocol errors.

When it fires

  • A §4.2 absence is returned as a JSON-RPC error
  • A §4.3 error envelope is returned as a JSON-RPC error rather than as a tool result

How to fix it

Return absence and contract errors as ordinary tool results carrying the full envelope

  1. Return absence and contract errors as ordinary tool results carrying the full envelope
  2. Reserve protocol errors for malformed requests: unknown tool, schema-invalid input
