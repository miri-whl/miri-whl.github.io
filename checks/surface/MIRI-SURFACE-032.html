MIRI-SURFACE-032 — Distinguishes an absent `api-index` from an empty one

Distinguishes an absent api-index from an empty one

must severity MEDIUM · 3 weight 6 Discovery Contract

Definition: standards/consumption/checks/MIRI-SURFACE-032.yaml · view · raw

Violation
{"ok": true, "present": true, "entries": {}} # package ships no sdk-manifest.json
Compliant
{"schema_version": "1", "ok": true, "present": false, "package": "greet_bare", "reason": "package ships no sdk-manifest.json"}

Why this matters

entries: {} says the package's surface, as filtered, is empty — a statement about the package. present: false says there is no manifest to derive an index from. A consumer cannot recover the difference once collapsed, and reading the former as the latter is exactly the absence-implies-non-existence inference the contract forbids elsewhere.

Definition

Surface obligation from the Discovery Contract. This check verifies: Distinguishes an absent api-index from an empty one.

When it fires

  • A package shipping no sdk-manifest.json gets present: true with an empty entries
  • A query matching nothing returns present: false rather than an empty entries

How to fix it

Return present: false with no entries key when the manifest is absent

  1. Return present: false with no entries key when the manifest is absent
  2. Return present: true with an empty entries when the manifest exists and the filter matched nothing
