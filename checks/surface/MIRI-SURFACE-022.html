MIRI-SURFACE-022 — Discovers import-free; executes nothing

Discovers import-free; executes nothing

must severity CRITICAL · 5 weight 5 Discovery ContractLifecycle and Security Metadata §9.2

Definition: standards/consumption/checks/MIRI-SURFACE-022.yaml · view · raw

Violation
importlib.import_module(pkg) # to read its __doc__ for the summary
Compliant
importlib.util.find_spec(pkg) # location only; metadata read from disk, never executed

Why this matters

Discovery runs over every installed package, including ones nobody has vetted. If locating metadata imports the target, a hostile package gains code execution merely by being installed and enumerated — the query surface becomes the attack. The same logic covers fetching: resolving a publisher-declared URL would turn publisher-controlled data into server-side requests.

Definition

Surface obligation from the Discovery Contract. This check verifies: Discovers import-free; executes nothing and fetches nothing.

When it fires

  • Any query imports the target package or executes any of its code
  • A package that cannot be resolved without importing is imported rather than reported NOT_DISCOVERABLE
  • Resolving a dotted package value imports the parent package on the way to the target (§3.0)
  • The surface serves a request from an interpreter that has the target environment on its import path, so that a .pth file, sitecustomize, usercustomize, or an eagerly loaded entry-point plugin executed publisher code before the first request arrived. Import-freedom is a property of the process, not of the request handler, and the hostile-import canary detects only the handler path

How to fix it

Resolve locations through the import system's path finders and read files; never import the target

  1. Resolve locations through the import system's path finders and read files; never import the target
  2. Reject a dotted package before attempting resolution, so the parent is never imported either
