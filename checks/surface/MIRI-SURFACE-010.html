MIRI-SURFACE-010 — Reports absence as `ok: true, present: false` — never as an error

Reports absence as ok: true, present: false — never as an error

must severity CRITICAL · 5 weight 8 Discovery Contract

Definition: standards/consumption/checks/MIRI-SURFACE-010.yaml · view · raw

Violation
{"error": "no MIRI metadata for greet_bare"} # is this absent, or did the lookup fail?
Compliant
{"schema_version": "1", "ok": true, "present": false, "package": "greet_bare", "name": "lifecycle.json", "reason": "package ships no lifecycle.json"}

Why this matters

Absence and failure mean different things and a consumer must act differently on each. The reference implementation currently conflates them — it returns absence as a success whose text is an ad-hoc error object — which is why the contract names conforming this the first implementation task. A consumer's honest-degradation conformance is only checkable if the surface makes the distinction first.

Definition

Surface obligation from the Discovery Contract. This check verifies: Reports absence as ok: true, present: false — never as an error.

When it fires

  • A query for a document the package does not ship returns ok: false or an error object
  • Absence is signalled by an empty success with no present: false
  • present is absent from a document-returning response

How to fix it

Return ok: true, present: false, no payload key, and a free-text reason

  1. Return ok: true, present: false, no payload key, and a free-text reason
  2. Keep ok and present orthogonal: they answer different questions and neither implies the other
