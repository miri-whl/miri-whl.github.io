Why this matters

Name-string filtering is not confinement. A whitelisted usage-patterns.json shipped as a symlink to a private key contains no traversal sequence and no absolute prefix, passes every string check, and is then read with the surface's own filesystem privileges. Editable and source-tree installs preserve symlinks, which is exactly the shape the fixtures are built in.

Definition

Surface obligation from the Discovery Contract. This check verifies: Confines the resolved path; rejects symlinks and traversal.

When it fires

  • A name carrying a directory prefix, absolute prefix, or traversal sequence is accepted or normalized
  • The resolved realpath lies outside the package's agent-metadata/ directory and is served
  • A symbolic link is followed rather than rejected

How to fix it

Treat name as a single path segment; reject anything else rather than normalizing it

  1. Treat name as a single path segment; reject anything else rather than normalizing it
  2. Resolve, realpath, and require a regular file physically inside the directory; reject symlinks outright
