MIRI-SURFACE-033 — Offers and scopes cursor continuation

Offers cursor continuation and rejects an out-of-scope cursor

must severity LOW · 1 weight 2 Discovery Contract

Definition: standards/consumption/checks/MIRI-SURFACE-033.yaml · view · raw

Violation
truncated: true with next_cursor, then that cursor returns page one again
Compliant
truncated: true with next_cursor, which returns the following entries in the same ordering

Why this matters

Continuation is what makes a capped surface completable in-band instead of forcing a consumer to guess at what it did not see. The failure this catches is worse than absence. A cursor that silently restarts hands the consumer page one labelled as page two, so it believes it has read the whole surface having read a prefix twice. Rejecting a cursor is always safe; honoring one incorrectly is not.

Definition

Surface obligation from the Discovery Contract (3.5.1). A surface that truncates a listing it can continue MUST return next_cursor, MUST accept that value to continue the same ordering, and MUST reject a cursor whose scope has changed as INVALID_CURSOR rather than silently restarting. A surface that retains no cursor state conforms by rejecting every cursor and emitting none; what it MUST NOT do is emit a token it will not honor. Ordering itself is scored by MIRI-SURFACE-031.

When it fires

  • A truncated response omits next_cursor where the surface can continue
  • A supplied cursor restarts the ordering rather than continuing it
  • A cursor presented with a changed operation, package, cap, or filter input is honored rather than rejected
  • A scope-changed or expired cursor is answered with INVALID_INPUT, or as absence, rather than INVALID_CURSOR
  • The surface emits next_cursor but rejects every cursor presented back to it

How to fix it

Return next_cursor on truncation, continue the same ordering, and reject out-of-scope cursors as INVALID_CURSOR

  1. Return next_cursor on truncation and accept it as cursor to continue the same ordering
  2. Reject a cursor whose scope has changed as INVALID_CURSOR, never by restarting
  3. If the surface keeps no cursor state, emit no next_cursor and reject every cursor as INVALID_CURSOR
