MIRI-SURFACE-001 — Stamps `schema_version` on every response

Stamps schema_version on every response

Why this matters

A consumer pins on schema_version to detect a wire-shape change. Without it a surface can alter its envelope silently and every consumer built against the old shape misreads the new one with no signal that anything moved. This is the same convention MIRI-CLI-010 enforces for producer tooling, applied to the query surface.

Definition

Surface obligation from the Discovery Contract. This check verifies: Stamps schema_version on every response.

When it fires

  • Any operation returns a response with no top-level schema_version
  • schema_version is present but nested inside the payload rather than at the envelope's top level

How to fix it

Stamp the envelope in one shared code path so no operation can emit an unstamped response

  1. Stamp the envelope in one shared code path so no operation can emit an unstamped response
  2. Version it independently of the transport's protocol version and of any version field inside the payload
