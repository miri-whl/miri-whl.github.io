Why this matters

The servable set is closed on a stated principle — only schema-governed documents are servable, and no free-form natural-language document ever is — because prose is the highest-risk payload a publisher controls and a document with no schema has no property a consumer can verify before it reaches a model's context. A surface that extends the set reopens the injection channel refusing prompt-templates.md was meant to close.

Definition

Surface obligation from the Discovery Contract. This check verifies: Serves only the closed servable set; refuses anything else.

When it fires

  • A request for prompt-templates.md, README.md, or any document outside §3.2.1's set returns the file
  • A name absent from the package's list.documents is served
  • The surface returns a filesystem error rather than DOCUMENT_NOT_SERVABLE

How to fix it

Check the requested name against the closed set before touching the filesystem

  1. Check the requested name against the closed set before touching the filesystem
  2. Return DOCUMENT_NOT_SERVABLE for anything else — never the file, never a filesystem error
