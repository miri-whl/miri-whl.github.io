Verify what you downloaded

A definitions package is a supply-chain root: reweight one MUST to zero and every wheel passes. Three things let you check it without trusting the host.

  1. The file hash. The index carries the wheel's sha256, so pip install --index-url verifies what it downloads; sha256sum -c SHA256SUMS checks it out of band. Two builds of one tag on one machine produce identical bytes — entry timestamps are fixed at write time — but the wheel is not reproducible across setuptools versions, which are unpinned, so a rebuild months later may differ.
  2. The pin. Inside the wheel, manifest.json carries checks_commit_sha — the full 40-character commit, never a tag, because a tag is a movable label — and content_sha256 over every definition and schema in sorted order. Recompute it from the source tree at that commit and it must match.
  3. Provenance. The release job attests build provenance for the wheel (gh attestation verify).

How an artifact gets here

Nothing on this page is uploaded by hand. A release tag pushes to .github/workflows/publish-checks.yml, which runs the same validators the repository gates on (make validate, make consistency), builds the wheel with tools/build_checks_wheel.py, scores it with the reference linter, attests it, and attaches it to the release for that tag. The repository stays the source of truth; this is a derived output, like this site.
